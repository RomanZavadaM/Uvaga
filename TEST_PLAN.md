# TEST_PLAN — критерії до коду
## Етап 0: docs-only
Наявні START, RULES, STATE, WORKLOG, HANDOFF, REQUIREMENTS, ARCHITECTURE, SOURCES, LICENSE, COPYRIGHT, THIRD_PARTY_NOTICES; лінки несуперечливі, немає ключів/API token, статус не видає недоведене за перевірене; новий ШІ незалежно може знайти наступну дію.
## Етап 1: синтетична модель подій (лише після дозволу)
Вхідні синтетичні тривога/відбій/дубль/запізнення/неправильний timestamp/мережевий збій. PASS: офіційний відбій лише підтверджений; дублікати не множаться; втрата даних не означає безпеку; докази тестів зафіксовані.
## Перед будь-яким розгортанням
Окремо перевіряти API-умови, надійність, навантаження, безпеку, privacy, фонові push Android/iOS, доступність і відкоти. CI не замінює живе приймання.

## Таблиця незалежних docs-only сценаріїв
1. Із чистої сесії відкрити START/HANDOFF та вказати одну наступну дію, не звертаючись до central dev-strategy.
2. Перевірити, що між REQUIREMENTS, ARCHITECTURE, SOURCE_VALIDATION немає твердження «TTL = відбій».
3. Переконатися, що неофіційний канал не може скасувати офіційну тривогу, а копії одного повідомлення не стають незалежними доказами.
4. Зіставити всі посилання та статуси з фактичними GitHub branch/PR; не вимагати наявності CI, якого ще немає.
5. Перевірити, що власницька ліцензія не перевизначає ліцензії залежностей, ключі й приватні дані відсутні.
6. Підтвердити, що Drive checkpoint index не видається за архів Git або повне дзеркало.
Результат окремого незалежного виконавця має містити дату, його ідентифікацію, знайдені дефекти й явний PASS/FAIL для кожного сценарію. Самоперевірка автора не дорівнює незалежному PASS.
