# BACKUP_AND_SYNC — ТривогА

GitHub — авторитетний стан коду, документації, рішень, журналу та PR. Google Drive — одностороння копія з GitHub; редагування дзеркала не переписує GitHub.

## Що зберігаємо
- Git-історію, теги, прийняту документацію, відкриті PR і контрольні пакети.
- Незлиту унікальну роботу — захищений checkpoint у гілці або окремий датований архів, незалежний від робочої сесії.
- Release assets, налаштування сервісу та користувацькі дані — після появи; секрети окремо, не в публічному GitHub/Drive.
- Тимчасові оперативні події за замовчуванням НЕ архівуємо без визначеної мети; аварійний state snapshot може бути потрібний для відновлення, але TTL додаткової інформації не скасовує активну офіційну тривогу.

## Точки збереження
Після значущого checkpoint, PR merge і релізу — датований знімок; записати базовий SHA, дату, контрольну суму, місце, результат завантаження. Дзеркало PROJECT зберігає актуальні START/RULES/STATE/HANDOFF/WORKLOG; CHECKPOINTS — контрольні версії; BACKUPS — окремі датовані знімки; VERIFICATION — перевірки відновлення.

## Перевірка
Принаймні до першого реального розгортання виконати пробне відновлення Git-стану та документів з архіву в ізольованому середовищі; результат, SHA, помилки — у VERIFICATION/WORKLOG. Google Drive sync не називати резервною копією. Стан «не синхронізовано» фіксувати як борг, не блокувати дозволений docs-only етап.
