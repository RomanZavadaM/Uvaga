# r27 — Проєкт оперативного отримання повідомлень про загрози та визначення територій

Статус: **DESIGN ONLY / NOT APPROVED FOR LIVE INTEGRATION**. 2026-11-02.
Це погоджувальна архітектура. Жодного live-запиту, токена, webhook, production, push, GPS, публікації чи відстеження рухомих військових цілей на цьому етапі.

## Мета і межі

ТривогА має показувати **офіційні стани тривог** та **окремі перевірені цивільні попередження** з географічним охопленням до області/району/громади, коли це підтверджено першоджерелом. Не будувати карту позицій, маршрутів, курсів або координат військових цілей у реальному часі, не виводити географію точніше за перевірену адміністративну територію.

## Види повідомлень і пріоритет довіри

1. **Офіційний сигнал**: оголошення, зміна охоплення, підтверджений відбій для визначеної території та визначеного типу загрози. Лише авторизований і технічно перевірений офіційний адаптер може оновлювати official state.
2. **Офіційне цивільне попередження**: хімічна, радіаційна, пожежна, природна чи інша небезпека; показувати категорію, територію, час, джерело і дії для населення, лише коли прямо заявлені офіційною установою.
3. **Додаткова інформація від агрегатора / редакційна**: окрема інформаційна картка із походженням і позначкою невизначеності; не змінює офіційного стану тривоги та не дозволяє відбій.

Не виводити з тексту повідомлення неоголошену територію, маршрут об'єкта, координати цілі чи прогнози. Якщо тип загрози невідомий — `unspecified`, а не вигаданий.

## Кандидатні джерела (без підключення)

- UkraineAlarm: задокументовані `/api/v3/alerts`, `/api/v3/alerts/{regionId}`, `/api/v3/alerts/status`, регіони і webhook; доступ потребує окремого прийняття оферти/дозволу власника: https://api.ukrainealarm.com/ , https://github.com/UkraineAlarm/UkraineAlarm-javascript/blob/master/docs/AlertsApi.md
- alerts.in.ua: документовані статуси області/району/громади й типи загроз: https://devs.alerts.in.ua/v3/ ; агрегатор як незалежне допоміжне джерело, НЕ автоматична офіційна атестація. Обмеження частоти, дозвіл і правила потребують перевірки на дату інтеграції.
- ДСНС, ОВА, офіційні органи місцевого самоврядування: офіційні тексти цивільного захисту, вручну погоджені канали, без несанкціонованого парсингу чи автоматичної переоцінки офіційного сигналу.
- Правова рамка цивільного оповіщення: постанова КМУ №733 — характер, місце, можлива зона небезпеки та заходи безпеки: https://zakon.rada.gov.ua/laws/show/733-2017-%D0%BF

## Потік даних

```
Approved source adapter (server side, credentials isolated)
 → bounded fetch / signed webhook admission / retry + backoff
 → raw immutable event envelope + source timestamp + received_at
 → schema validation / official-source identity / dedup / ordering
 → territory ID mapping (audited, versioned KATOTTG snapshot)
 → typed event and authoritative state reducer (per territory × alert category)
 → freshness & outage guard (stale/unavailable never creates clear)
 → safety presentation and coarse territory subscriptions
 → read-only desktop/mobile/web API and optional future consented notifications
```

Насамперед створити **офлайнові fixtures й контрактні тести**. Server-side polling/push вибирати лише після власницького рішення, оферти та вимірювання SLA/обмежень. Не закладати вигадані інтервали оновлень.

## Контракт повідомлення (концептуально)

- `source_id`, `source_role` (approved-official/secondary), `provider_event_id`, `event_version_id` (immutable);
- `issued_at`, `observed_at`, `received_at` UTC; `source_freshness` independent from `alert_state`;
- `alert_kind` (air_raid, artillery, chemical, radiation, civil_other, unspecified), `signal` (start, update, clear, advisory);
- `provider_territory_id`, `katottg_snapshot_id`, `canonical_territory_id`, `scope_level` (oblast, raion, hromada), `mapping_confidence` (verified / unresolved);
- `authenticity_evidence`, `source_url`, `revision`, `supersedes`, `raw_payload_digest`.

Усі поля із зовнішнього джерела не довірені, доки не пройшли перевірку. Збереження raw payload повинно бути контрольованим, без секретів чи приватних ідентифікаторів.

## Території та локалізація

**Географічна локалізація:** канонічна ієрархія область → район → громада з версійним KATOTTG та явно перевіреною таблицею provider-ID. Область не означає, що кожна громада має окреме підтвердження; для часткового охоплення потрібна точна перевірена множина. Невизначені ID — карантин / unknown, не довільна прив'язка. При перетині різних зон не скасовувати активний сигнал більш вузького охоплення через відбій іншої зони.

**Мовна локалізація:** першою українська, решта мов інтерфейсу — лише переклади категорій/пояснень; оригінальний текст і атрибуція джерела доступні. Переклад не змінює тип загрози, назву офіційного сигналу або його охоплення.

**Вибір користувача:** підписка на області/райони/громади вручну; геолокація пристрою тільки як майбутня окрема opt-in функція, не вмикати зараз. Жодних поточних координат військових об'єктів.

## Fail-safe правила

- Відбій дозволяється лише через **новішу, прийняту, підтверджену офіційну подію clear** для правильної території та категорії.
- Timeout/TTL/network error/auth failure/HTTP 429/schema error не створюють clear; при застарілому відбої показувати «Відбій потребує повторного підтвердження».
- Update іншої категорії не змінює активну категорію; суперечливі або одночасні події не перезаписують останній підтверджений стан без окремого правила.
- Повторна доставка дедуплікується за immutable event identity; зміни версії оформлюються окремою revision.
- Коли джерела суперечать, агрегатор не скасовує official; повідомлення про суперечність відокремлене від головного сигналу.
- При відновленні зв'язку спершу повна перевірена синхронізація, потім лише дельти; при провалі — unknown/stale.
- Ніякого змішування категорій офіційних тривог і редакційних цивільних повідомлень.

## Вимоги до швидкості без ризику

- Виміряти `source-issued → received → validated → rendered` на синтетичних даних (p50/p95/p99), окремо час stale detection і recovery.
- Моніторити джерело, вік останнього успішного fetch, 429/backoff, schema drift, unmapped territory, duplicates, clock skew.
- Обмежена черга, idempotency, backpressure, exponential backoff з jitter, circuit breaker; не обіцяти «миттєвість», поки немає контракту й SLA джерела.
- Жоден кеш чи офлайн-режим не видає стару позначку «відбій» як поточно актуальну.

## Етапи реалізації

**A (наступний дозволений):** офлайнова модель `ThreatCategory + TerritoryScopedEvent`, синтетичні сценарії декількох одночасних категорій, конфліктів і часткового охоплення, тести та документація; жодних live-адаптерів.

**B (після рев'ю):** offline source-adapter contract, fixture-driven schema validation та replay/recovery tests з законсервованими тестовими зразками.

**C (власницьке схвалення обов'язкове):** законність і ліцензія кожного джерела, підтвердження доступу, дизайн серверного розподілу ключів, privacy/security assessment, окрема згода на live source.

**D (окремі owner gates):** закрите live-приймання, політика затримок, незалежний safety audit, manual Windows/mobile acceptance; production / public alerts / push — окремі рішення.
