# r32 — Львів: перший контрольний сценарій приймання інформації

Статус: **синтетичний тестовий сценарій, НЕ живий моніторинг**. Обране місто: **Львів**, адміністративний зв'язок: місто → Львівська міська територіальна громада → Львівський район → Львівська область. Коди громади/району мають бути підтверджені за версійним КАТОТТГ; не вигадувати ідентифікатори.

## Що перевіряємо
- Стан офіційної повітряної тривоги, час публікації та отримання, територія офіційного сигналу.
- Тип повітряної загрози **тільки за компетентним першоджерелом** (ракетна, БПЛА, не уточнено).
- Час останнього оновлення, ознака stale/unavailable, підстава довіри.
- Незалежність джерел: UkraineAlarm і передрук в агрегаторі НЕ два незалежні підтвердження; окремий офіційний канал може бути незалежним, якщо перевірено, що він сам випустив повідомлення.
- Якщо попередження стосується області загалом, не вигадувати окреме повідомлення про місто.
- Якщо одна загроза закінчилась, інші категорії/локальні записи не скасовуються.

## Тестові вхідні дані
1. Джерело A: синтетичний офіційний сигнал для UA-46 з issued_at=100, received_at=102.
2. Джерело B: копія A з origin_id=A:event-1, received_at=103; результат: **1 первинне походження, не 2 підтвердження**.
3. Джерело C: незалежно видане підтверджене узагальнене повідомлення для адміністративної території, issued_at=104; показувати окреме походження.
4. Підозрілий масовий запис про інший тип небезпеки без підтвердженого першоджерела; не підвищувати до офіційного стану.
5. Розрив зв'язку, повтор, запізніле повідомлення, відновлення і перевірена синхронізація; жодна подія не породжує автоматичний «відбій».

## Вихід контрольної картки
Львів; адміністративне охоплення; офіційний стан; підтверджений вид загрози або «не уточнено»; час повідомлення й отримання; дата останнього успішного контакту; першоджерела та дублікати; позначка невизначеності; офіційна рекомендація щодо укриття.

**Заборонено**: оцінка координат/напрямку/швидкості/маршруту військових цілей чи часу підльоту до Львова. Немає live API, токенів, публічних сигналів або deployment.

## Приймання
Синтетичний тест засвідчує фільтрацію передруків, некоректних джерел і помилкового відбою. Після цього — окреме дослідження прав та доступних API й погодження реального підключення власником.
